# Implementation Plan: Final Frontend QA + Polish (Travel SaaS Platform)

**Branch**: `011-frontend-qa-polish` | **Date**: 2026-06-06 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/011-frontend-qa-polish/spec.md`

## Summary

Run a **full frontend QA, polish, and production-readiness pass** over the entire Travel SaaS Platform built in Specs 001–010 — **32 existing pages** across three surfaces (public `pages/` ×16, merchant `dashboard/` ×9, owner `admin/` ×7) plus the seven shared JS modules (`ui.js`, `main.js`, `dashboard.js`, `discovery.js`, `content.js`, `member.js`, `admin.js`) and the shared CSS build — and capture the result in a single deliverable: **`travel-saas-frontend/QA-FRONTEND-CHECKLIST.md`**. This is an **audit → categorize → surgically fix → re-verify → report** cycle, **not** a feature build: it adds no product features, no new pages, no new framework, no backend, no visual-identity change, and removes no working section. The **4 Spec 008 pages** (`dashboard/bookings.html`, `dashboard/booking-details.html`, `dashboard/customers.html`, `dashboard/customer-details.html`) are confirmed **absent and stay unbuilt** — the audit's job is to guarantee nothing links to them as a real destination (every reference resolves to a safe coming-soon affordance, never a 404).

The pass covers fourteen audit areas: **(1) page inventory** (all 32 render; 4 documented-absent), **(2) navigation** (every link/CTA/row-action/modal-action resolves; correct cross-folder relative paths `pages/`→siblings, `dashboard/`→`../pages/`, `admin/`→`../pages/`+`../dashboard/`; no bare `#`/dead control; stale coming-soon CTAs repointed), **(3) responsive** (no horizontal overflow at 320/360/390/768/1024/1280px; tables→cards or scroll-with-affordance; ≥44px targets), **(4) RTL** (logical properties; `dir="ltr"` on coupon codes/emails/URLs/invoice ids/amounts; correct breadcrumb order + drawer side), **(5) visual consistency** (one design system across all surfaces), **(6) JS interactions** (drawers/dropdowns/modals/toasts/copy/toggles/filters/tabs/row-menus/bulk/confirm all work; no console error; no duplicate-listener repeated toasts; body-scroll lock/unlock), **(7) forms** (labels + inline `aria-invalid`/`aria-describedby` errors + honest success, no unintended reload), **(8) content honesty** (no false live/real-backend claims; approved safe Arabic/English wording; session-only state), **(9) SEO/semantics** (one `<h1>`, hierarchy, Arabic title/meta, landmarks, valid non-misleading JSON-LD), **(10) accessibility** (WCAG 2.1 AA: focus, keyboard, labels, `aria-live`, icon-button labels, contrast, reduced-motion; axe where the environment permits, else a documented manual audit), **(11) performance/assets** (no external CDN, local fonts, `defer` scripts, no broken image/SVG paths, no duplicate scripts, no chart/table library, no runtime-fetch dependency for core content; `npm run build` + stack-grep pass), **(12) file/structure cleanup** (no stray backups/dead demo code; consistent data files; styleguide/components still render), **(13) end-to-end flows** (public visitor, merchant, admin each complete with no dead control), **(14) non-regression** (Specs 001–010 still render after any link/JS/CSS edit).

**Technical approach**: **Static analysis + scripted gates first, surgical fixes second, re-verify third, honest report last.** The audit is driven by repeatable shell/Node checks over the source tree (a link/asset-path crawler, the stack-compliance grep, `npm run build`, `npx html-validate`, `node --check` per JS module, `stylelint`, an `<h1>`/landmark/`dir="ltr"`/`defer`/`data-label` structural sweep, and a forbidden-claim copy grep), each emitting a categorized issue list. **Fixes are minimal and surgical** — repoint a wrong relative path, add a missing `aria-label`/`scope`/`dir="ltr"`, add `type="button"`, convert a bare `#` or a 404-bound link into a `data-coming-soon` toast, normalize an ad-hoc style to a token, correct a media query, fix a dishonest string — always **reusing the existing `window.TUI` primitives and `main.js`'s declarative `data-*` delegation**, never introducing a framework, never rewriting a page, never breaking a shared asset other specs depend on (every fix is followed by a non-regression re-render check of the affected surface). **No browser is available to the executor**, so "clean console" and "visual/responsive rendering" are verified by the strongest available static proxies (JS syntax/guard checks, `html-validate`, asset-existence crawl, structural grep for overflow-prone patterns and table→cards affordances) and the genuinely browser-only confirmations are scripted into `quickstart.md` for the user to run via `npm run serve` — this limitation is documented honestly in the report rather than asserted as done. Two **fix-safety constraints learned from the Spec 010 QA gate are carried forward**: (a) **Prettier v3 corrupts inline HTML `<style>` blocks** (escapes `<`→`\3c`, rewrites `@media (max-width:Npx)`→range syntax that breaks the html-validate tokenizer), so `prettier --write` MUST NOT touch HTML containing inline `<style>` — the audit keeps/extends the `.prettierignore` coverage and never reformats those pages; (b) the repo's `.htmlvalidate.json` is aligned to the project's actual HTML5 output (lowercase doctype, self-closing voids) and MUST stay consistent so the gate reflects real defects, not formatter drift. State remains **session-only** (no fix introduces real persistence). The sole new artifact is the **`QA-FRONTEND-CHECKLIST.md`** report; all other changes are in-place corrections to existing files.

## Technical Context

**Language/Version**: HTML5, CSS3 via the existing Tailwind CSS v3.4 local build (PostCSS/Autoprefixer); vanilla JavaScript (ES2020, classic `defer` scripts, no bundler). Build/runtime tooling: Node.js ≥ 18 LTS + npm (unchanged from Specs 001–010).
**Primary Dependencies**: None added. Audit/verify tooling already installed as devDependencies — `tailwindcss@^3.4` (`npm run build`), `html-validate@^9.7.1` (`npx html-validate`), `stylelint@^16` + `stylelint-config-standard` (`npm run lint:css`), `prettier@^3.4` (`npm run format`, **restricted** away from inline-`<style>` HTML), `@axe-core/cli@^4.9` (`npm run audit:a11y`, requires a served origin), `serve@^14` (`npm run serve` for manual browser checks). Fixes reuse the existing `window.TUI` namespace (`toast` / `modal.open|close` / `drawer.open|close|toggle` / `validateForm` / `copyToClipboard` / `prefersReducedMotion`) and `main.js`'s declarative `data-*` delegation (`data-coming-soon`, `data-modal-open|close`, `data-drawer-open|close|drawer`, `data-copy`/`data-copy-target`, `data-toast`/`data-toast-type`, `data-validate`/`data-frontend-form`/`data-success-toast`, `data-year`). **No runtime framework, no CDN, no external chart/table/date library** is added — the audit verifies their continued absence.
**Storage**: N/A — no backend/database/CMS/account/billing/session store is added or relied upon. All content stays realistic, clearly-mock **static HTML**; all state (filters/sort/search selections, mock added/edited rows, toggled statuses/feature flags, checklist checks, range/compare toggles, bulk selection, typed form values) is **in-memory/session-only** and restores to mock defaults on reload. The audit verifies that no copy claims server persistence (لا يتم الحفظ على خادم في هذه النسخة) and that no fix introduces real persistence.
**Testing**: Repeatable QA gates (no unit-test framework, consistent with Specs 001–010): `npm run build` (must succeed, regenerates `assets/css/tailwind.css`); the **stack-compliance grep** over all html/js/css excluding `node_modules` for `react|vue|angular|bootstrap|jquery|cdn.tailwindcss|alert(|confirm(|prompt(` (must be zero real hits; documented false positives allowed); `npx html-validate` over all 32 pages (zero errors); `node --check` per JS module; `npm run lint:css`; a **link/asset-path crawler** (every internal `href`/`src`/asset reference resolves to an existing file or a documented coming-soon affordance); a **structural sweep** (one `<h1>` per page, semantic landmarks, `defer` on scripts, `dir="ltr"` on Latin runs, `data-label`/overflow-x table→cards affordances, `aria-*` on icon-only buttons and dynamic regions); a **forbidden-claim copy grep**; and **axe-core** per representative page where a served origin is available, else a documented **manual WCAG 2.1 AA audit**. The browser-only confirmations (live console-clean, pixel responsive/RTL/visual) are scripted in `quickstart.md` for the user to run via `npm run serve`. The deliverable `QA-FRONTEND-CHECKLIST.md` records every gate with pass/fail and any limitation.
**Target Platform**: Modern evergreen browsers — Chrome, Edge, Firefox, iOS/macOS Safari — last 2 major versions. Mobile-first (~320–360px up to desktop); the audit verifies dense merchant/admin tables collapse to stacked labeled cards (or scroll with a visible affordance), grids reflow to one column, and sidebars become drawers, with no horizontal overflow.
**Project Type**: Static frontend web application (single project) — QA/polish pass over the existing three-surface platform. No backend tier; no new surface.
**Performance Goals**: Preserve the existing budget — each page interactive in < 2s under Lighthouse mobile "Slow 4G" + 4× CPU throttle; minified CSS reused; **zero runtime CDN requests** (verified); **no external chart/table library** (verified, CSS-only visuals); no runtime `fetch` dependency for core content (verified). Fixes must not regress these (e.g., no new blocking script, no un-`defer`'d JS, no newly-added external asset).
**Constraints**: Approved stack ONLY (no React/Vue/Angular/Bootstrap/jQuery/Tailwind-CDN; no external chart/table/date library; no `alert()`/`confirm()`/`prompt()`) — the audit both **verifies** this and **must not violate** it when fixing. Arabic-RTL default + English-ready (LTR must not structurally break). WCAG 2.1 AA. Standalone backend-ready pages (render without JS; no runtime-fetch core dependency). **No dead interactions** (every control navigates/modals/drawers/toggles/copies/filters/validates/toasts/coming-soon/confirms; the 4 absent Spec 008 pages + any unbuilt owner settings/billing/support stay coming-soon — no 404). SEO/semantics baseline (semantic HTML, single `<h1>`, hierarchy, Arabic title/meta, valid non-misleading JSON-LD). **Product-honesty wording** on every mutating control. **Fix-safety**: surgical edits only; reuse `window.TUI` + `main.js` `data-*`; **do not** rewrite pages, redesign identity, change the constitution, add features/pages/frameworks/backend, or remove working sections; **do not** break a shared asset (`ui.js`/`main.js`/`dashboard.js`/`discovery.js`/`content.js`/`member.js`/`admin.js`, the CSS build, `partials/`, `assets/data/*.json`, the sprite) that other specs depend on — re-render the affected surface after each shared-file edit; **do not** run `prettier --write` over HTML that contains inline `<style>` (Prettier v3 corruption) — keep/extend `.prettierignore`; keep `.htmlvalidate.json` aligned to real output. Styleguide/components MUST keep rendering and MUST NOT be deleted.
**Scale/Scope**: 32 existing pages audited (public ×16: index, compare, deals, coupons, deal-details, destinations, destination-details, blog, article, login, register, saved-deals, price-alerts, profile, styleguide, components; merchant ×9: index, deals, create-deal, edit-deal, coupons, create-coupon, analytics, integrations, settings; owner ×7: index, companies, company-details, plans, subscriptions, analytics, content) + 7 shared JS modules + the CSS build + shared `partials/`/`assets/`. 4 Spec 008 pages documented-absent.
