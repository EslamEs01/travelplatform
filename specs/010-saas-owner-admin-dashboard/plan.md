# Implementation Plan: SaaS Owner Admin Dashboard (Travel SaaS Platform)

**Branch**: `010-saas-owner-admin-dashboard` | **Date**: 2026-06-05 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/010-saas-owner-admin-dashboard/spec.md`

## Summary

Build the **SaaS owner/admin surface** — the platform-owner control room that sits above the public site (002–005) and the merchant dashboard (006–009) — as **seven new standalone pages inside a new `travel-saas-frontend/admin/` directory**: `index.html` (`admin-overview`), `companies.html` (`admin-companies`), `company-details.html` (`admin-company-details`), `plans.html` (`admin-plans`), `subscriptions.html` (`admin-subscriptions`), `analytics.html` (`admin-analytics`), and `content.html` (`admin-content`). The owner manages the travel companies using the SaaS, the SaaS plans and their limits, subscriptions and mock billing, platform-wide analytics, platform content, and integration health — entirely as a **frontend-only, honest prototype**: nothing is really authenticated, suspended, plan-changed, billed, invoiced, paid, impersonated, monitored, published, exported, emailed, or persisted; every mutating surface carries the approved safe wording (بيانات تجريبية / واجهة أمامية فقط / إجراء تجريبي / لا يتم الحفظ على خادم في هذه النسخة / لا يتم تنفيذ تغيير حقيقي / لا توجد مدفوعات فعلية / لا يتم تسجيل دخول كالشركة فعليًا / قابل للربط لاحقًا) while staying backend-ready. **Overview**: page header (4 quick-action buttons + safe note), ≥10 platform KPI cards, a platform activity feed (≥10 items), a top-companies table (≥8 rows → `company-details.html?id=`), integration-health cards (8), subscription-alert cards, CSS/static analytics previews (5 — **no chart library**), a quick-admin-actions grid, an admin-notes/tasks checklist, and empty/skeleton patterns. **Companies**: header + ≥8 stats cards, search + 8 filters + 6-option sort with an `aria-live` result count + removable chips + reset, a ≥12-row responsive table (table→cards at 360px) with per-row action menus (view / change-plan / suspend-reactivate / extend-trial / add-note / contact-owner / **login-as disabled-safe**), bulk actions (bulk-suspend via a custom confirm modal), Add-Company / Change-Plan / Suspend-Reactivate / Add-Note modals (validated → toast), 7 segment cards that filter the list, empty/skeleton states, and a FAQ (≥5). **Company details**: a complete default mock company (works with or without `?id=`) — profile header + actions, frontend-only note, subscription summary, ≥8 usage progress bars (near-limit warnings), a ≥10-item activity timeline, a top-deals table, booking-stats cards, integration-status rows (8), a mock billing timeline (view/download/send), admin notes + a support/follow-up panel, the per-company action modals (incl. reset-usage confirm + login-as safety modal), and a FAQ (≥5). **Plans**: header + monthly/yearly toggle, four plan cards (Starter/Growth/Pro/Enterprise) with mock prices + limits + feature flags + active-company counts + actions (edit/duplicate/disable-enable/view-companies), a features-comparison table (≥14 rows × 4 plans), a validated create/edit modal, a duplicate action, a disable **custom confirm** modal (companies-not-affected warning), a companies-on-plan preview, and a FAQ (≥5). **Subscriptions**: header + 8 stats cards (incl. MRR/ARR estimates), search + filters + 5-option sort with a result count, a ≥12-row table with per-row actions (view-company / change-plan / extend-trial / mark-paid / send-reminder / cancel / view-invoice / download-invoice), bulk actions, a subscription-detail modal, an invoice mock modal (line items), an extend-trial modal, a cancel **custom confirm** modal, and a FAQ (≥5). **Analytics**: header (date-range + compare toggle + export mock + safe note), ≥12 KPI cards, **eight** CSS/static chart-like visuals (**no chart library**), five insight tables (top companies / destinations / deals / integration errors / high-risk subscriptions), recommendation cards (≥5), an export/report mock modal, and a FAQ (≥5). **Content**: header + 8 content stats, six tabs (Homepage Sections / Destinations / Blog Posts / Featured Deals / Featured Coupons / Pending Review) with **all panels in the DOM**, each tab's table/cards + actions, a validated create/edit modal, feature/unfeature toggles, publish/unpublish + delete **custom confirm** modals, pending-review approve/reject, a homepage preview panel, and a FAQ (≥5).

**Technical approach**: Static composition + believable mock content + progressive enhancement, on a **new, dedicated admin shell** that is visually *related to* the product (same Spec 001 tokens and foundation components) yet **clearly distinct** from the merchant dashboard shell. The merchant shell is a **dark teal/lagoon** rail (`--sidebar-bg:#042B2E`, active `#0E8186`) via page-scoped `.dash-*` classes; the admin shell is a **dark slate (`ink`) rail with a gold (`sunset`) accent** via page-scoped `.admin-*` classes and an explicit "مالك المنصة / Owner Admin" brand label — same palette tokens, different role, so the owner can tell at a glance they are in the platform-admin context. The admin shell (RTL sidebar + topbar + mobile drawer + scrim + breadcrumb + page header + notifications/user-menu/quick-action dropdowns + small footer) is authored once and repeated consistently across all seven pages; only the active sidebar item, breadcrumb, and page header vary. Each page authors its own `<head>` from the `partials/head.html` conventions (`../assets/css/tailwind.css`, Cairo font preload, favicon, theme-color, `robots noindex`) exactly as the dashboard pages do — it does **not** inline the public marketing `header.html`/`footer.html`. All **core content is static HTML** so every page renders without JavaScript (Constitution III): every KPI card, activity item, table row, integration/alert/segment/plan/insight/recommendation card, comparison table, all six content tab panels, the usage bars, the billing timeline, and every modal's *content container* ship statically; the seven JSON catalogs are **backend-ready reference data** and the baseline does **not** depend on `fetch`. A **new `src/js/admin.js`** (loaded `defer` after `ui.js` + `main.js`, mirroring the `dashboard.js` IIFE pattern) carries the admin logic: an `_ADMIN_PAGES` guard list keyed on `<html data-page>`, shared primitives (a `TUI.toast` wrapper, a `DropdownController` for the three topbar dropdowns, a row-action-menu controller, a `TUI.validateForm` submit wrapper, a shared confirm-modal helper, a generic client-side **filter/sort/search engine** that updates an `aria-live` count + removable chips, a `slugify` helper, and the sidebar-drawer wiring), then **seven per-page controllers** dispatched by `data-page`. Drawers, modals, coming-soon, copy, toast, year, and form-validation hooks reuse `main.js`'s existing declarative `data-*` delegation (`data-drawer-open|close`, `data-modal-open|close`, `data-coming-soon`, `data-copy`/`data-copy-target`, `data-toast`/`data-toast-type`, `data-validate`/`data-frontend-form`/`data-success-toast`, `data-year`) and `window.TUI` (`toast` / `modal.open|close` / `drawer` / `validateForm` / `copyToClipboard` / `prefersReducedMotion`) **unchanged** — so `ui.js`, `main.js`, and `dashboard.js` (and `discovery.js`/`content.js`/`member.js`) are **not modified**. All chart-like visuals (overview previews + the eight analytics visuals + usage/plan bars) are **pure CSS/HTML** built from existing tokens in a small page-scoped `<style>` per page (the same precedent the homepage, content pages, and Spec 006–009 dashboard pages use) — **no external chart/table library**; the dense tables collapse to stacked labeled cards at 360px using the Spec 006–009 table→cards pattern. All confirmations (bulk-suspend, suspend/reactivate, cancel-subscription, disable-plan, reset-usage, publish/unpublish, delete-content, login-as safety) use `.modal`/`window.TUI.modal` — **no `alert()`/`confirm()`/`prompt()`**. "Login as company" is always rendered **disabled/safe** and, where activated, opens a safety modal stating impersonation is inactive. State is **session-only** (added rows, toggled statuses, checklist/feature toggles, filter selections); reload restores mock defaults. New believable mock content lives in **seven additive backend-ready catalogs** — `assets/data/admin-overview.json`, `admin-companies.json`, `admin-plans.json`, `admin-subscriptions.json`, `admin-platform-analytics.json`, `admin-content.json`, `admin-integration-health.json` — reusing `deals.json`/`merchant-deals.json`/`merchant-coupons.json`/`destinations-full.json`/`articles.json` ids where a deal/coupon/destination/article is referenced so identity stays consistent across the platform; where an intended catalog is absent (`merchant-bookings.json`/`merchant-customers.json` were never created — only `merchant-bookings-preview.json` exists, and the Spec 008 merchant bookings/customers pages were never built), the admin catalogs are **self-sufficient** because baseline content is static HTML. The admin sidebar links the seven real pages, deep-links `مراقبة التكاملات`→`analytics.html#integrations`, makes `الإعدادات` a **coming-soon toast** (no admin-settings page in scope), and links `العودة للموقع`→`../pages/index.html` and `لوحة الشركات`→`../dashboard/index.html`. The unbuilt merchant bookings/customers pages and any owner billing/support surface beyond these seven pages stay **coming-soon** (no 404). The **only** foundation touches are additive: a **one-line `tailwind.config.js`** edit adding `./admin/**/*.html` to the `content` globs (the build does not yet scan `admin/`), a **new `src/js/admin.js`**, **seven new JSON catalogs**, and **additive sprite symbols only if a genuinely missing icon is needed** (the 67-symbol sprite already covers building/credit-card/award/pie-chart/activity/plug/users/bar-chart/map-pin/shield/etc.; candidates if missing: `dollar-sign`, `file-text`, `layers`, `server`). **No existing public/member/merchant page is edited** (merchant pages already keep the owner-admin surface coming-soon; no link rewiring is required), no existing JS behavior changes, no new visual identity, no backend.

## Technical Context

**Language/Version**: HTML5, CSS3 authored via the existing Tailwind CSS v3.4 local build (PostCSS/Autoprefixer); vanilla JavaScript (ES2020, classic `defer` scripts — no bundler). Build-time runtime: Node.js ≥ 18 LTS + npm (unchanged from Spec 001–009).
**Primary Dependencies**: None added. Reuses installed `tailwindcss@^3.4`, `postcss`, `autoprefixer`, `@tailwindcss/forms`; the existing `window.TUI` namespace (`toast` / `modal.open|close` / `drawer.open|close|toggle` / `validateForm(form,{rules})` / `copyToClipboard` / `prefersReducedMotion`); and `main.js`'s declarative `data-*` delegation (`data-coming-soon`, `data-modal-open|close`, `data-drawer-open|close|drawer`, `data-copy`/`data-copy-target`, `data-toast`/`data-toast-type`, `data-validate`/`data-frontend-form`/`data-success-toast`, `data-year`). A **new `src/js/admin.js`** adds the admin shell wiring + seven per-page controllers, mirroring the `dashboard.js` IIFE/guard/dispatch pattern and reusing the same primitive shapes (DropdownController, row-menu, validateAndSubmit, confirm-modal helper) — it does **not** import or modify `dashboard.js`. **No runtime framework, no CDN, no external chart/table library** — all chart-like visuals are pure CSS/HTML. The filter/sort engine, tabs, modals, toggles, and forms operate on the in-page DOM; the JSON catalogs are backend-ready reference data and the baseline content does **not** depend on `fetch` (a page MAY read a `#hash` deep link or an inline `<script type="application/json">` block for enhancement only).
**Storage**: N/A — no backend/database/CMS/account/billing store. Mock content is realistic, clearly-mock **static HTML** mirroring seven new local `assets/data/*.json` files (`admin-overview`, `admin-companies`, `admin-plans`, `admin-subscriptions`, `admin-platform-analytics`, `admin-content`, `admin-integration-health`; `deals.json`/`merchant-deals.json`/`merchant-coupons.json`/`destinations-full.json`/`articles.json` referenced unchanged). All state (filter/sort/search selections, an added/edited row, a toggled status or feature flag, checklist checks, monthly/yearly + compare + date-range selections, bulk selection, typed form values) is **in-memory/session-only**; reload restores mock defaults; nothing is persisted to a server. `localStorage` MAY be an optional convenience only and no copy claims permanent/server storage (لا يتم الحفظ على خادم في هذه النسخة).
**Testing**: Manual QA against the per-page "done" checklist (`quickstart.md`) + automated accessibility audit (axe-core) targeting WCAG 2.1 AA, HTML validation (`html-validate`) for all seven pages, and Prettier/Stylelint. The stack-compliance grep (forbidden tech + browser dialogs + external chart/table library + external CDN) across the seven pages and `admin.js` is a hard gate. No unit-test framework (consistent with Spec 001–009). A `qa-results.md` is produced after implementation.
**Target Platform**: Modern evergreen browsers — Chrome, Edge, Firefox, iOS/macOS Safari — last 2 major versions. Mobile-first (~320–360px up to desktop); the pages must feel close to a native app on mobile (the companies/subscriptions/comparison/insight tables collapse to stacked labeled cards; the KPI grids, chart visuals, plan cards, segment cards, content tabs, usage bars, and forms reflow to one column; the sidebar becomes a drawer with a scrim).
**Project Type**: Static frontend web application (single project). This phase builds the **SaaS owner/admin** surface the constitution names (Principle VIII): seven new pages in a new `admin/` directory. No backend tier.
**Performance Goals**: Each page interactive in < 2s under Lighthouse mobile "Slow 4G" (≈1.6 Mbps, 150 ms RTT) + 4× CPU throttle; minified CSS reused; zero runtime CDN requests; **no external chart/table library** (CSS-only visuals); the filter/sort engine, tabs, modals, toggles, and forms operate on the in-page DOM (no network).
**Constraints**: Approved stack ONLY (no React/Vue/Angular/Bootstrap/jQuery/Tailwind-CDN; **no external chart/table library**; no `alert()`/`confirm()`/`prompt()`); Arabic-RTL default + English-ready (LTR must not structurally break); WCAG 2.1 AA; standalone backend-ready pages (render without JS, structured for later Django templating); no dead interactions (every control navigates/modals/toasts/toggles/copies/validates; `الإعدادات` + unbuilt merchant bookings/customers + owner billing/support stay coming-soon — no 404s); SEO/semantics baseline (semantic HTML, single `<h1>` per page, heading hierarchy, breadcrumb, Arabic title/meta; `robots noindex` acceptable for these admin surfaces); **product-honesty wording** on every mutating control (never a real admin login, company suspension, plan/price change, subscription billing, invoice, payment, impersonation, integration monitoring, content publishing, export, email/WhatsApp, or persistence). **Reuse the Spec 001 foundation unchanged** except: a one-line additive `tailwind.config.js` glob (`./admin/**/*.html`), a new `src/js/admin.js`, seven additive JSON catalogs, and additive sprite symbols only if needed. **Do not modify** `ui.js`/`main.js`/`dashboard.js`/`discovery.js`/`content.js`/`member.js`, the public/member `pages/`, the merchant `dashboard/` pages, or `partials/header.html`/`footer.html`; preserve all existing sections; **do not use the public marketing header/footer** on admin pages; do not change the constitution; no new visual identity.
**Scale/Scope**: Seven new pages in a new `admin/` surface + one new admin shell + a new `admin.js` (shell wiring + 7 controllers) + seven new JSON catalogs + a one-line Tailwind glob + additive sprite symbols if needed. Per-page minima — **index.html**: 4 quick actions; **≥10** KPI cards; activity feed **≥10**; top-companies **≥8** rows; **8** integration-health cards; subscription alerts (5 types); **5** CSS previews; quick-actions (7); checklist (5); empty/skeleton. **companies.html**: **≥8** stats; search + **8** filters + **6**-option sort + count/chips/reset; **≥12** rows (13 cols); 7 row actions (login-as disabled-safe); bulk actions (bulk-suspend confirm); 4 modals; **7** segment cards; empty/skeleton; FAQ **≥5**. **company-details.html**: profile header + 7 actions; subscription summary; **≥8** usage bars; timeline **≥10**; top-deals table; **7** booking-stat cards; **8** integration rows; billing timeline; notes + support panel; 7 action modals; FAQ **≥5**. **plans.html**: **4** plan cards; monthly/yearly toggle; comparison table **≥14** rows; create/edit modal; duplicate; disable confirm; companies-on-plan preview; FAQ **≥5**. **subscriptions.html**: **8** stats; search + filters + **5**-option sort + count; **≥12** rows (12 cols); 8 row actions; bulk actions; detail modal; invoice modal; extend-trial modal; cancel confirm; FAQ **≥5**. **analytics.html**: date-range + compare + export; **≥12** KPI cards; **8** CSS visuals; **5** tables; **≥5** recommendation cards; export modal; FAQ **≥5**. **content.html**: **8** stats; **6** tabs (all panels in DOM); 7 homepage sections + 5 other tab tables; create/edit modal; feature toggle; publish/unpublish + delete confirms; pending-review approve/reject; homepage preview; FAQ **≥5**. Navigation: admin sidebar links the 7 pages + integration deep-link + settings coming-soon + back-to-site + merchant-dashboard; unbuilt surfaces stay coming-soon.
